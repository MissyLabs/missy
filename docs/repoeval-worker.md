# RepoEval worker protocol

`missy.repoeval.worker.execute_worker` accepts a `WorkerRequest`, trusted `approve(digest, manifest)` callback, and injected `ProviderBroker`. It makes **no** Nomad calls, network calls of its own, repository checkout reads, shell calls, patch applications, or writes. The broker is the only provider boundary; tests inject a stub. No live provider or cluster access has been validated.

Preflight recomputes `sha256_json(manifest)` and asks the trusted callback to approve that exact canonical digest. The callback must verify an external signature or immutable **project-scoped** approval record with expiry/revocation and an authorized signer; `approved: true` inside a manifest is meaningless. It then checks finite one-attempt execution, approved provider/model entry, exact class and validator, fixed validator parameter names, offline network policy, digest-pinned non-placeholder image, finite CPU/memory/disk requests, immutable commit identity, SHA-256 of every frozen input byte, total input ≤1 MB, a 120-second maximum requested timeout, and capped tokens/budget. Bundled workloads have empty providers and a placeholder image and **are not runnable** without separate reviewed authorization. No arbitrary path is opened by this protocol. An external dispatcher must separately verify snapshot/image identity and pin a signed, content-addressed input bundle.

Three deterministic classes: repository-orientation compares an exact structured JSON answer to a frozen factual oracle tied to the commit; tool-call validates the envelope and schema, then interprets restricted arithmetic AST in-process without executing the tool; patch-generation checks constrained diff paths but **always fails** until a hardened disposable sandbox proves actual application and tests. Never interpret a patch diff as a verified repair. This conservative orientation oracle requires verbatim JSON, which the prose bundled prompt may not elicit reliably; that is a case-design limitation, not a provider failure.

Result includes status/reason, manifest/request/response SHA-256, validator ID, score and canonical report SHA-256. No raw response, fixture, exception, provider credential, or provider metadata is persisted. Refusals precede any provider call; post-call failures preserve digests when available. These digests do not themselves constitute uploaded artifacts or proof of retention, scanning, or redaction. A trusted artifact pipeline must verify actual object bytes by digest before publication.

The Python function is **not** a security sandbox or preemptive timeout. A hung malicious provider adapter can block its process, and untrusted Python code must never be loaded/executed from a fixture. Outer worker isolation must impose a hard wallclock deadline, CPU/memory/disk quotas, read-only root, non-root identity, no writable host mounts, no external network except a separately enforced broker boundary, and kill/cleanup on timeout. The existing Nomad module produces plans only and does not enforce deployment here. Until isolation and an approved patch verification sandbox exist, do not deploy this as a general untrusted-code executor.
